## Context
Peek is reportedly unusable for viewers. The live signaling health and `/ice` endpoints return HTTP 200, and the deployed page includes the previously missing answer handler. Current code still contains definite viewer and reconnect defects; these are not evidence that NAT is the cause of the reported errors.

Confirmed issues:
- `peek/index.html:579–585` attaches the stream but never reveals `vidWrap`, which defaults to `display:none`.
- `peek-node/mailbox.js:193–200` delivers an offer once per tab SID; clicking Join again with that SID does not request a new negotiation.
- `peek/index.html:505–529` stops viewer polling on connection, lets its server claim expire, and reports every negotiation timeout as “the host never answered.”
- Async signaling handlers use mutable global connections and are dispatched without awaiting; retries can overlap, and queued ICE is discarded by `joinAnswer()`.

## Recommended repair
Keep the existing Node mailbox, server-issued codes, direct WebRTC, and Host/Join UI. No TURN, new provider, warm-up machinery, or unrelated refactor.

### 1. Fix viewer playback and error handling
**File:** `peek/index.html`
- Reuse `gotRemoteStream()`, `show()`, and `setStatus()` to reveal the player, assemble received tracks safely when `event.streams` is empty, and attempt playback. Show a small inline playback action only if the browser actually blocks playback.
- Report the actual failing stage: signaling unreachable, no offer received, answer creation/submission failed, or peer connection failed. Keep retry available; check JSON errors as well as fetch failures.
- Make each attempt own its peer connection and cancellable requests. Ignore events/results from stopped attempts, prevent overlapping Join actions/poll loops, and process signaling in order without dropping early ICE.

### 2. Repair join/rejoin and leave lifecycle
**Files:** `peek-node/mailbox.js`, `peek-node/server.js`, `peek/index.html`
- Add an explicit fresh-join/retry handshake using the existing SID, with a negotiation identifier so stale answer/ICE messages cannot affect the replacement connection. Preserve the immediate pre-deposited offer for first joins.
- Keep viewer signaling alive while connected so its seat stays fresh and host closure is delivered. Leaving releases the seat; retry requests a fresh host offer and clears stale negotiation queues.
- Reuse existing `ready`, per-role `wake()`, and room creation logic. Replace the obsolete host `post('create')` recovery with correct room-expired handling.
- Validate room ownership for lifecycle actions and recheck room/session state after parked polls wake; cancelled polls must not consume messages.
- Add a protocol/version tell to health responses and clear errors for mismatched deployments. Preserve the exact Altare startup message.

### 3. Add focused regression coverage and deployment notes
**Files:** `peek-node/mailbox.test.js` (new), `peek-node/package.json`, `peek-node/README.md`
- Use Node's built-in test runner for first join, same-tab retry, leave/rejoin, active-seat protection, stale ICE isolation, cancelled polls, and host close/expired room.
- Update README to match the actual protocol and explain that client and server changes must be deployed together.
